# Desktop app

The Electron app: what it shows and how it talks to the core.

```bash
pnpm desktop            # dev mode with hot reload
pnpm -C atelier-desktop smoke   # build + Playwright smoke test (echo backend, no network)
```

Open a folder, pick a backend and a model, and chat. When `~/.atelier/profiles.json` has profiles, a `profile` selector lists them (asked with `profiles.list` each time the core is ready): `by layers (active: <name>)` lets the core resolve it, and a name is sent as `session.start.profile` for the next session; a chosen name the core no longer lists (after a restart, or when the list fails) goes back to `by layers`, so what the selector shows is what is sent; the backend and model pickers are still sent, so they replace the orchestrator's. Next to it a `mode` selector (`default`, `normal`, `auto`, `yolo`) picks the permission mode of the next session: `default` sends no `mode`, so the core uses the default saved with `/mode default`; the others are sent as `session.start.mode` (see [Permission modes](sandbox.md#permission-modes)). The status bar shows the model with its effort (`opus · effort high`), the session's permission mode as a selector (`normal`, `auto` or `yolo`, from the main agent's `session_started`; `yolo` in the warning style; changing it sends `session.set_mode` and shows the mode the core answered, and if the command fails the previous mode stays and the error is shown like any other) and the session's profile (`profile: cheap (repo)`, or `profile: default`; kept when a later `session_started` carries none), with what it sets for each role in its tooltip. Each tool call shows as a row with its status; `bash` commands ask for approval in a card that shows invisible and control characters as visible markers; an `edit` of a file outside the working directory asks in the same card (`Edit a file outside the working directory?`, with `edit <absolute path>`; a `write` asks as `Write a file outside the working directory?`, with `write <absolute path>`). Every turn ends with a one-line summary of its tokens and cost that unfolds into the token breakdown and, when the turn had more than one part, one line per part (`main`, `declare`, `verify`, `lenses`, `refuter`, `correction`, `validator`) with its tokens, requests and cost, and who ran in it as the CLI's `phases:` line says it (`main · 3K tokens · 1 request · on claude-opus-5-5 effective xhigh`); the status bar shows the core status, whether `bash` is sandboxed, warnings and the latest error; a command the sandbox stopped lists why under its row (see [Sandbox (macOS)](sandbox.md)). If the core process dies, the app says so and offers a restart.

The desktop starts the core with Electron's own Node (no system Node needed) and talks to it over the Atelier protocol (version 5): one JSON message per line on stdin/stdout, a `hello` with the protocol version, an `id` on every command and exactly one response per command, and events tagged with their session.
